# 论文插图的构图与验收

先确定读者要从这张图回答什么，再选内容。例如“谁负责退回补件”适合泳道图，“什么条件导致退回”适合流程图。同一套图沿用需求中的角色名、业务动词和实体名。节点中留下能区分对象的最短名称；图题、枚举解释和长注播放在正文或图注。

## 概念 E-R 图

1. 先列实体，再逐项核对“参与实体、联系名称、每个实体端的基数”。相同实体用同一别名；同一对实体之间的两种业务联系各用一个菱形。自关联保留两个参与端，三元联系保留一个联系标识及其全部参与者。只有名称清单时可以生成实体草图，关系和基数待材料确认。
2. 用真实关系驱动排版。链、中心辐射、环和独立业务组由服务端分别处理。实体数量相同也可能需要不同布局。正文总览优先呈现实体与联系，属性在实体详图中展开；联系自身的属性连到对应菱形。物理表的字段、类型、外键约束放数据库 ERD。
3. 逐条从实体边沿经过基数和菱形读到另一端。除具有共同语义的连接端点以外，任意两条线交叉、相切、形成 T 接头或共线重合，均须返工。线穿过无关图元或文字、图元相压、基数漂到另一条线上，也须返工。服务端拆成关系视图时，保留视图标题和同名实体的对应说明。按联系标识及参与端核对分图并集，防止漏掉跨页关系。
4. 示例中，一位职员可以负责多个项目，每个项目有一位负责人；职员和项目之间还存在多对多的参与关系。这两条联系应能独立追踪。

```text
entity 职员 as Staff
entity 项目 as Project
relationship 负责 as Lead
relationship 参与 as Participate
Staff (1) -- Lead -- (n) Project
Staff (m) -- Participate -- (n) Project
```

## 流程图与泳道图

- 一个判断回答一个问题。“材料齐全？”的否分支退回补件，是分支再判断“超过四小时？”。若问题是“异动类型”，休学、复学、转专业可以作为三个互斥出口。条件写在出边上，办理动作写在框内。
- 主流程从上向下读。检查每个分支从哪个出口发出，在何处汇合；重试边回到实际重做的步骤。正向线与返回线应可分别追踪，箭头落在目标轮廓上。
- 回到同列步骤时，先检查能否用一条直线接到空闲端口；若正向线已占用中心端口，回线可以接到轮廓上的另一点。多路判断的条件应贴各自独立的线段，尤其要分清从菱形同侧引出的相邻出口。
- 长旁路或跨层退回与另一支拥挤时，比较放到主列两侧的走法。优先选能顺着箭头连续读完、折弯少且原有成功与失败分支都保留的版本。调整后逐条核对源节点、条件和目标节点，再检查实际导出的 SVG；不要靠删边、改条件、加图注来改善外观。
- 泳道表示责任主体，步骤用 `in` 声明归属。跨道箭头表示交接，退回线应留在泳道区域内，并与泳道分隔线错开。先分清“任选一路后汇合”和“多路都完成再继续”：前者用 `merge`，后者用 `fork` 和 `join`。沿每条并行支路走一遍，确认都接入同步条。
- 下面的资料校验和历史查询可以独立执行，汇总必须等两者完成。

```text
lane 受理组 as Desk
lane 核验组 as Review
start 开始 as S in Desk
fork F in Desk
action 核对申请资料 as A in Desk
action 查询历史记录 as B in Review
join J in Desk
action 汇总核验结果 as C in Desk
end 结束 as E in Desk
S -> F
F -> A
F -> B
A -> J
B -> J
J -> C
C -> E
```

## 其他图型

| 图型 | 排版时保留的结构 | 看图时重点检查 |
| --- | --- | --- |
| 用例 | 每个真实角色独立成图，共享用例沿用同名 | 关联线接到椭圆边沿，include/extend 的箭头方向和文字可辨 |
| 功能结构、分层架构 | 同一层级使用一致的命名粒度，组件归入所属层 | 父子关系可追踪，框内留白足够；分层之间保留间隔 |
| 时序、活动 | 参与者与消息时序明确；判断、并行、同步分别表达 | 消息名没有压住生命线或片段标题，每个守卫对应自己的出口 |
| 类、构件、部署 | 类成员、接口、制品分别属于明确的宿主 | 类框包住最长签名；关系端符号朝向正确；依赖线避开接口名 |
| 数据流、数据库 ERD | 数据流命名，数据存储和表结构使用各自记法 | 数据流名紧邻本线，主外键及可选性与实际定义一致 |

## 从论文样本中取舍

先按文件内容排除完全重复的副本，再从窄长、接近方形和宽幅图片中抽查。长宽比只用于覆盖不同样式。逐个判断图元的真实含义：读者能指出当前步骤、每条条件边的去向和回线落点时，这个局部才可作为示例。对缺少判断、拿功能树充当流程、缩到栏宽后字迹难辨的部分，仅记录为反例。参考图里没有说明的业务规则仍须回到需求核实。

论文流程图使用 `paper` 输出一张完整原图。图号、图注、缩放及页面排版由下游 AI 处理。先从开始节点逐条走通成功、异常和重试路径，检查每个箭头落点；再核对线段、文字和符号边界。仅当业务本身有清楚的职责或阶段边界时，在同图内用间距组织最多三组步骤；不绘制阶段括线或侧边说明。

## 以最终插入尺寸验收

同一组论文图优先用黑白 SVG。统一字体和字号，例如单图 render 可用 `--theme mono --font "SimSun, serif" --font-size 16`（原始尺寸约 12 磅）。先在实际栏宽看阅读顺序和字号，再放大看接点和文字；文档软件单独缩放某一张图会改变它的实际字号。

发现压字或连错时，记录“图名、源节点、目标节点、具体问题”，先修 DSL 的条件、归属、冗长名称或业务范围，重新渲染并查看同一处。流程图出现几何问题时修正走线和条件标注，并在同一张图核对完整模型；概念 E-R 图可保留需要的关系视图。交付实际看过的版本，指出仍未通过的项；单凭接口返回成功无法判断版面质量。
